## 🎯 Слайд 1: Огляд системи

### Що це?
**Fujikura Applicators Management System** — комплексне рішення для управління аплікаторами на виробництві.

### Для чого?
- 📊 Відстеження місцезнаходження аплікаторів
- 🔧 Управління статусами та обслуговуванням
- 📜 Ведення повної історії переміщень
- 🔒 Контроль доступу на основі ролей
- ⚠️ Управління обмеженнями машин

### Хто використовує?
- Адміністратори системи
- Технічні працівники
- Оператори машин

## 🏭 Слайд 5: Локації виробництва

### 1. Aplicator Room (Кімната аплікаторів)
- **Тип**: Основне сховище
- **Місткість**: 300 комірок
- **Аплікатори**: Усі нові або повернені
- **Статус**: AVAILABLE

### 2. Дільниця обслуговування
- **Тип**: Обслуговування і налаштування
- **Місткість**: Необмежена
- **Процес**: Налаштування, перевірка
- **Статус**: SERVICE
- **Дія**: Тільки технік може підтвердити готовність

### 3. Дільниця нарізки
- **Машини**: G01 - G30 (30 штук)
- **Макс на машину**: 5 аплікаторів
  - На машині: 2 (робочі)
  - На стелажі: 3 (запас)
- **Статус**: CUTTING

### 4. Дільниця кримпування
- **Машини**: P01 - P05 (5 штук)
- **Макс на машину**: 3 аплікатори
  - На машині: 1 (робочий)
  - На стелажі: 2 (запас)
- **Статус**: CRIMPING

### 5. Дільниця заблокованих
- **Тип**: Сховище
- **Призначення**: Несправні аплікатори
- **Статус**: BLOCKED
- **Дія**: Лише технік може розблокувати

### 6. Дільниця неактивних
- **Тип**: Сховище
- **Призначення**: Виведені з експлуатації
- **Статус**: INACTIVE
- **Дія**: Лише технік може активувати

## ⚠️ Слайд 10: Сповіщення і обмеження

### Обмеження машин нарізки
```
При спробі додати 6-й аплікатор:
"На машині вже знаходиться максимальна кількість аплікаторів (5).
Поверніть непотрібні аплікатори до дільниці обслуговування."
```

### Обмеження машин кримпування
```
При спробі додати 4-й аплікатор:
"На машині вже знаходиться максимальна кількість аплікаторів (3).
Поверніть непотрібні аплікатори до дільниці обслуговування."
```

### Статус конфлікти
```
Якщо аплікатор вже на машині:
"Аплікатор вже знаходиться на машині GXX"
або
"Аплікатор вже знаходиться на машині PXX"
```

### Заблоковані аплікатори
```
Якщо спробувати використати заблокований:
"Аплікатор заблокований та недоступний для використання"
```

## 📈 Слайд 14: Потенційні проблеми (20+)

### Concurrency Issues
1. **Одночасне редагування**: Два користувачі одночасно переміщають один аплікатор
   - **Рішення**: Оптимістичне або песимістичне блокування

2. **Race condition**: Дублювання переміщень при повільному мережевому з'єднанні
   - **Рішення**: Ідемпотентні операції, унікальні токени

3. **Session conflicts**: Втрачена сесія під час операції
   - **Рішення**: Session refresh, CSRF token rotation

### Data Integrity
4. **Некоректний статус**: Аплікатор має статус CUTTING але локація Aplicator Room
   - **Рішення**: Валідація на БД рівні, транзакції

5. **Розрахунок лімітів**: Неправильний підрахунок аплікаторів на машині
   - **Рішення**: Trigger у БД, кеші з інвалідацією

6. **Видалення активного**: Видалення аплікатора з машини тоді як він робить роботу
   - **Рішення**: Перевірка статусу перед видаленням

### Permission Issues
7. **Некоректні права**: Оператор може редагувати користувачів
   - **Рішення**: Ретельна перевірка в декораторах

8. **Privilege escalation**: Користувач змінює свою роль через API
   - **Рішення**: Перевірка прав, логування спроб

9. **Sessjon hijacking**: Викрадення сесії іншого користувача
   - **Рішення**: Secure cookies, IP validation

### API Issues
10. **CSRF attack**: POST без CSRF токена
    - **Рішення**: CSRF middleware, токени в формах

11. **SQL injection**: Пошук аплікатора по числовому ID
    - **Рішення**: Parameterized queries (вже робиться ORM)

12. **XSS attack**: Вставка JavaScript в коментар
    - **Рішення**: Automatic escaping, Content-Security-Policy

### Performance Issues
13. **Slow queries**: Повільне завантаження історії з 100k записів
    - **Рішення**: Індексація, пагінація, кеширование

14. **Memory leak**: Збільшення пам'яті при тривалій роботі
    - **Рішення**: Профілювання, memory cleanup

15. **Timeout**: Довге переміщення 1000 аплікаторів
    - **Рішення**: Batch операції, async tasks

### Data Loss
16. **No backup**: Втрата БД при краху сервера
    - **Рішення**: Автоматичні backup'и, репліка

17. **Cascade delete**: Видалення користувача видаляє всю його історію
    - **Рішення**: Soft delete, архівування

18. **Partial update**: Сбій під час оновлення, дані у невизначеному стані
    - **Рішення**: Транзакції, rollback

### Input Validation
19. **Empty fields**: Збереження пустих значень
    - **Рішення**: Required fields, server-side validation

20. **Duplicate entries**: Два аплікатора з однаковим номером
    - **Рішення**: Unique constraint, duplicate check

### Maintenance
21. **Database growth**: БД розривається (SQLite має обмеження ~1TB)
    - **Рішення**: Міграція на PostgreSQL, архівування старих записів

22. **Configuration leak**: Вливання чутливих даних (SECRET_KEY) в git
    - **Рішення**: .env файли, секрети в environment variables

## ❓ Слайд 17: FAQ

### Q: Що робити якщо забув пароль?
A: Свяжіться з адміністратором, який може скинути пароль.

### Q: Як додати нового користувача?
A: Тільки адміністратор може додавати користувачів через сторінку /admin/users

### Q: Чи можна змінити пароль?
A: Поточна версія не має цієї функції. Адміністратор може скинути пароль.

### Q: Як експортувати звіт?
A: Перейдіть на сторінку історії і використовуйте кнопку експорту (будет додано в майбутньому)

### Q: Чи захищені дані?
A: Так, використовуються сучасні методи шифрування та захисту.

### Q: Як часто коштує робити резервну копію?
A: Щодня о 02:00. Адміністратор відповідає за моніторинг резервних копій.
